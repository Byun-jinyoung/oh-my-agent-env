# 검증 규칙 (40-verification)

- 변경 범위에 맞는 가장 작은 신뢰 가능한 검증을 실행한다.
- shell은 `bash -n <script>`, JSON은 `python3 -m json.tool <file>`로 확인한다.
- 테스트는 관련성이 가장 높은 targeted test부터 실행하고, 영향이 크면 broader test를 추가한다.
- 검증을 실행할 수 없으면 이유와 남은 위험을 명시한다.
- 작업 완료를 주장하기 전에 검증 명령을 실제로 실행하고 출력을 확인한다. 근거 없이 "완료/통과"라고 말하지 않는다.
- 기능 구현 중 테스트가 필요할 때, 기존 테스트 스크립트와 로직이 비슷하면 **새 파일을 만들지 말고 해당 스크립트를 수정/확장**한다. 비슷한 검증을 흩어두지 말고 한 곳에 모은다.
- **false-green 위험을 명시한다** — 테스트가 엉뚱한 이유로 통과할 수 있는 경로(기준선을 검사 대상에서 파생, 프록시만 확인, 설정과 검증이 같은 코드 경로)를 먼저 짚고, 없으면 없다고 적는다.
- 버그 수정 테스트는 **재현된 버그에서 실패하고 의도한 계약에서 통과**하도록 만든다. 고친 뒤에만 돌려보고 통과했다고 하지 않는다.
- 내부 함수의 상태를 단정하기보다 **관찰 가능한 인터페이스**를 검증한다. 구현을 바꾸면 깨지는 테스트는 계약을 지키지 못한다.
