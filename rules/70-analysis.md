# 결과·실험 분석 (70-analysis)

연구/ML 작업에서 실험 결과·측정값·로그를 해석할 때의 규칙.

## 측정 우선

- 결과는 실제 metric·로그·파일로 확인하고 출처(run, config, split, seed, commit)를 연결한다.
- 단일 수치 대신 baseline, 이전 run, 목표치와 비교한다.
- 과학 계산이나 HPC 자원 사용에 관한 결론은 scheduler 출력, job metadata, 측정 로그
  같은 관측 가능한 근거로 확인한다. 자원 사용량·완료·재현 가능성을 추측하지 않는다.

## 비교의 공정성

- split·전처리·평가 코드·metric 방향이 같은지 확인한다.
- 분산과 seed 변동을 구분하고 1회 측정으로 우열을 단정하지 않는다.

## 해석의 절제

- 상관과 인과를 구분하고 성능 변화의 대안 가설을 확인한다.
- 결론에는 근거 + 반대 가설 + 신뢰도(높음/중간/낮음)를 함께 적는다.
- 데이터 누수(leakage) 의심 신호(비현실적 점수, train/val 경계 모호)를 먼저 점검한다.

## 지속 기록

- 명시 요청이나 accepted scope가 요구할 때만 vault·문서에 기록한다.
- 큰 결과는 복사하지 말고 승인된 artifact 경로를 참조한다.
- 지속 기록하는 분석 결정에는 무엇을·왜·어떤 근거로 정했는지 함께 적는다.

## 도구

- 설치된 도구의 실제 metric·log를 읽는다. 사용되지 않는 원장·wrapper를 새로 만들지 않는다.
